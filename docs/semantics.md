# Семантика SIPL: терми та їх обчислення

Використовується композиційна семантика курсу (М.С. Нікітченко, «Теорія програмування»;
Практикум, практична робота 2). Стан `st` - скінченна часткова функція `змінна → ціле`.

## Нотація термів

| Конструкція | Unicode | ASCII | Тип функції |
|---|---|---|---|
| присвоювання | `AS^x(A)` | `AS^x(A)` | стан → стан |
| послідовне виконання | `P1 • P2` | `P1 o P2` | стан → стан |
| розгалуження | `IF(B, P1, P2)` | `IF(B, P1, P2)` | стан → стан |
| цикл | `WH(B, P)` | `WH(B, P)` | стан → стан |
| skip | `id` | `id` | стан → стан |
| розіменування | `x⇒` | `x=>` | стан → ціле |
| константа | `5̅`, `T̅`, `F̅` | `#5`, `#T`, `#F` | стан → значення |
| суперпозиція | `S²(+, A1, A2)`, `S¹(¬, B)` | `S^2(+, A1, A2)`, `S^1(not, B)` | стан → значення |

Операції: `+ − × ÷`, відношення `< ≤ = ≠ > ≥`, логічні `∧ ∨ ¬`.

## Правила побудови (SEM-01)

```
⟦x := a⟧ = AS^x(⟦a⟧)                ⟦S1 ; S2⟧ = ⟦S1⟧ • ⟦S2⟧
⟦if b then S1 else S2⟧ = IF(⟦b⟧, ⟦S1⟧, ⟦S2⟧)
⟦while b do S⟧ = WH(⟦b⟧, ⟦S⟧)        ⟦begin S end⟧ = ⟦S⟧        ⟦skip⟧ = id
⟦n⟧ = n̅    ⟦x⟧ = x⇒    ⟦true⟧ = T̅    ⟦false⟧ = F̅
⟦a1 ∘ a2⟧ = S²(∘, ⟦a1⟧, ⟦a2⟧)        ⟦not b⟧ = S¹(¬, ⟦b⟧)
```

Побудова - рекурсивна (знизу вгору по AST); `sipl term FILE --steps` друкує кожне
застосоване правило з фрагментом коду. Композиція `•` асоціативна, тому
`(P1 • P2) • P3` друкується як `P1 • P2 • P3`.

Приклад (`examples/power.sipl`):

```
AS^R(1̅) • WH(S²(>, Y⇒, 0̅), AS^R(S²(×, R⇒, X⇒)) • AS^Y(S²(−, Y⇒, 1̅)))
```

## Правила обчислення (SEM-02)

`∇` - накладка (overlay), `⊥` - невизначеність.

| Правило | Формула |
|---|---|
| `AS` | `AS^x(A)(st) = st ∇ [x ↦ A(st)]` |
| `SEQ` | `(P1 • P2)(st) = P2(P1(st))` |
| `IF-T` / `IF-F` | `IF(B, P1, P2)(st) = P1(st)`, якщо `B(st)=T`; `= P2(st)`, якщо `B(st)=F` |
| `WH-T` | `WH(B, P)(st) = WH(B, P)(P(st))`, якщо `B(st)=T` |
| `WH-F` | `WH(B, P)(st) = st`, якщо `B(st)=F` |
| `ID` | `id(st) = st` |
| `CONST`, `BCONST` | `n̅(st) = n`, `T̅(st) = T`, `F̅(st) = F` |
| `DEN` | `x⇒(st) = st(x)`; `⊥`, якщо `x ∉ dom st` |
| `ARITH` | `S²(∘, A1, A2)(st) = A1(st) ∘ A2(st)`; `÷` на 0 дає `⊥` |
| `REL` | `S²(ρ, A1, A2)(st) = A1(st) ρ A2(st)` |
| `AND`, `OR` | сильна логіка Кліні: `T ∨ ⊥ = T`, `F ∧ ⊥ = F`, інакше `⊥` поширюється |
| `NOT` | `S¹(¬, B)(st) = ¬B(st)` |

Цілочисельне ділення `÷` округлює до нуля: `7 ÷ 2 = 3`, `(−7) ÷ 2 = −3`.

### Невизначеність і межі автоматизації

Результат - або кінцевий стан, або `⊥` з причиною:

* `UNBOUND` - розіменування змінної, якої немає у стані;
* `DIV_ZERO` - ділення на нуль;
* `UNDEFINED_CONDITION` - умова невизначена (за логікою Кліні);
* `STEP_LIMIT` - перевищено ліміт застосувань правил (`--max-steps`, типово 10 000).

`WH(B, P)` - найменша нерухома точка; вона обчислюється розгортанням. Зупинка програм
алгоритмічно нерозв'язна, тому інструмент **не вирішує** завершуваність: ліміт кроків -
інженерний запобіжник, а `STEP_LIMIT` означає «за N кроків результат не отримано».

## Трейс

Кожен запис трейсу: номер, глибина вкладеності, правило, `term_id` та `ast_id`
(зв'язок з термом і кодом), вхідний/вихідний стан (`st0`, `st1`, ...), значення та
пояснення. Переходи станів утворюють ланцюжок `st0 → st1 → …`, кожен перехід - одне
застосування `AS`.
